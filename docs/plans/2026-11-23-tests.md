# Plan: Unit- und E2E-Tests für die Konferenz-App

- **Datum:** 2026-11-23
- **Status:** Umgesetzt (2026-11-23)
- **Branch:** `feature/tests` (Basis `feature/mvp-konferenz-app`)

## 1. Ziel

Zwei Testprojekte sichern die Fachlichkeit des MVP ab: schnelle Unit-Tests ohne Infrastruktur und End-to-End-Tests gegen eine echte Postgres-Datenbank, die echte API über HTTP und den echten WASM-Client im Browser.

## 2. Anforderungen und Entscheidungen

| Thema | Entscheidung |
|---|---|
| Testframework | xUnit v3 auf der Microsoft Testing Platform (`global.json`: `"test": { "runner": "Microsoft.Testing.Platform" }`). Der VSTest-Modus wird mit dem .NET-11-SDK nicht mehr unterstützt. |
| Assertions | Plain xUnit `Assert`, keine zusätzliche Bibliothek |
| Erwartungswerte | Kommen aus der Spezifikation (README „API im Überblick“, MVP-Plan), nicht aus dem Code |
| Datenbank | `Testcontainers.PostgreSql`, ein Container pro Testlauf (xUnit-Assembly-Fixture) |
| API-Host | `WebApplicationFactory<Program>` mit `UseKestrel()` auf freiem Port, also echtes HTTP |
| Client-Host | `dotnet publish` des Clients beim ersten UI-Test. Ein statischer Kestrel-Host mit SPA-Fallback liefert ihn aus. |
| API-Adresse im Client | Playwright beantwortet `appsettings.json` per Route |
| Isolation | Eigene Konferenz mit eindeutigem Slug pro Test; die Seed-Konferenz wird nur gelesen |
| Selektoren | Rollen, Labels und Texte; Routenziele (`href`) statt CSS-Klassen |
| Fehlerdiagnose | Screenshot und Trace unter `bin/.../TestResults/playwright` |
